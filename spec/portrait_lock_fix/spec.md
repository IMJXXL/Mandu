# 需求规格：锁定竖屏容易失效

- **需求ID**: REQ-004
- **标题**: 锁定竖屏偏好失效修复
- **优先级**: P1（高）
- **基线 commit**: eb2ac412
- **状态**: 待评审

## 1. 背景与问题

用户反馈默认阅读偏好里的"锁定竖屏"（`SCREEN_ORIENTATION_SENSOR_PORTRAIT`）很容易失效，具体表现：
- 条漫（连续滚动模式）留空时竖屏锁定失效；
- 换一本漫画后也容易失效，需要重新打开设置才恢复。

根因方向：竖屏锁定状态在进书/切书/视图重建/条漫分支等路径上未被一致应用，或被某处重置为 `UNSPECIFIED`。需要先在漫画内设置一遍核实，确认修复点后再动。

## 2. 核心输入

1. 用户在阅读偏好/单本设置中选择的屏幕方向（含"锁定竖屏"）
2. 进书/切书/视图重建/条漫分支切换事件
3. 当前书籍的阅读模式（翻页/条漫）

## 3. 核心输出

1. Activity 的 `requestedOrientation` 设置
2. 按书记忆的方向偏好（`orientation_$bookId`）

## 4. EARS 需求

### 4.1 锁定竖屏稳定生效

**REQ-004-A**
WHEN 用户将屏幕方向设为"锁定竖屏" THE SYSTEM SHALL 在当前书籍的整个阅读会话内保持竖屏方向，不因翻页、切章、视图重建而丢失。

**REQ-004-B**
WHILE 当前书籍处于条漫（连续滚动）模式且屏幕方向设为"锁定竖屏" THE SYSTEM SHALL 保持竖屏方向，不因条漫留空、内容为空或分支切换而失效。

**REQ-004-C**
WHEN 用户从一本书切换到另一本书且新书的方向偏好为"锁定竖屏"（或继承默认偏好为锁定竖屏） THE SYSTEM SHALL 立即应用竖屏方向，不要求用户重新打开设置才生效。

**REQ-004-D**
WHEN 用户从一本书切换到另一本书且新书的方向偏好为"默认/跟随系统" THE SYSTEM SHALL 按新书偏好设置方向，不被前一本书的锁定竖屏状态残留影响。

### 4.2 核实后修复

**REQ-004-E**
WHEN 实施本需求前 THE SYSTEM SHALL 先在漫画内设置一遍"锁定竖屏"并核实失效场景，定位确切失效路径后再修复，禁止盲改。

### 4.3 约束

**REQ-004-F**
WHILE 锁定竖屏生效 THE SYSTEM SHALL NOT 因任何内部状态重置（配置重载、视图 release/re-setup、条漫分支判定）将方向回退为 `UNSPECIFIED` 或其他非竖屏值。

**REQ-004-G**
IF 用户未单独为某书设置方向 THEN THE SYSTEM SHALL 使用默认阅读偏好中的方向设置，且该默认值在进书时即时生效。

## 5. 验收条件

1. 设为锁定竖屏后，条漫留空/内容为空时仍保持竖屏。
2. 换一本书（新书偏好同为锁定竖屏）后立即竖屏，无需重开设置。
3. 换一本书（新书偏好为默认/跟随系统）后按新书偏好生效，不被前书残留影响。
4. 翻页、切章、视图重建过程中竖屏不丢失。
5. 修复前已先在漫画内核实失效路径，有据可查。

## 6. 职责边界

- 不负责横屏锁定（仅修竖屏锁定失效，横屏行为不在本次范围）
- 不负责双页/条漫模式本身的逻辑
- 不改变方向偏好的持久化键结构与按书记忆机制
