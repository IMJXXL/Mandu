# 需求规格：归档密码功能 UI 重构

- **需求ID**: REQ-001
- **标题**: 归档密码功能 UI 重构
- **优先级**: P1（高）
- **基线 commit**: eb2ac412
- **状态**: 待评审

## 1. 背景与问题

当前归档密码管理嵌在「文件夹管理」设置页的一个行内条目里，点击后弹出一个系统原生对话框（`showArchivePasswdsDialog`），用户靠换行在一个文本框里输入多个密码，体验简陋且易错。加密压缩包尝试全部已存密码仍失败时，现有逻辑可能以"没有内容""文件缺失"等无关提示兜底，而非明确引导用户输入密码。

## 2. 核心输入

1. 用户在归档密码管理界面的新增/删除操作
2. 加密压缩包打开请求（来自本地/SAF/SMB/WebDAV 来源）
3. 已存归档密码集合（`Settings.archivePasswds`，本地/SMB/WebDAV 三路共用）

## 3. 核心输出

1. 更新后的归档密码集合（持久化，跨来源共用）
2. 压缩包打开成功/失败结果
3. 密码输入请求弹窗（仅在自动尝试全部失败时弹出）

## 4. EARS 需求

### 4.1 独立管理界面

**REQ-001-A**
WHEN 用户从设置入口进入归档密码管理 THE SYSTEM SHALL 提供一个独立的全屏界面（非弹窗）用于管理归档密码列表。

**REQ-001-B**
WHEN 归档密码管理界面展示密码列表 THE SYSTEM SHALL 每条密码作为一个独立记录项显示，支持单条新增与单条删除。

**REQ-001-C**
WHEN 用户在归档密码管理界面执行系统返回手势（边缘返回/返回键） THE SYSTEM SHALL 返回到进入该界面的前一界面，不丢失已保存的密码修改。

### 4.2 密码自动尝试与兜底弹窗

**REQ-001-D**
WHEN 加密压缩包被打开且存在已存归档密码 THE SYSTEM SHALL 依次自动尝试已存密码，命中的密码优先使用。

**REQ-001-E**
WHEN 加密压缩包已尝试全部已存密码仍未打开 THE SYSTEM SHALL 弹出密码输入窗口让用户手动输入密码。

**REQ-001-F**
WHEN 加密压缩包打开失败且根因是密码错误或需要密码 THE SYSTEM SHALL NOT 以"没有内容""文件缺失""文件暂时找不到"等与密码无关的提示代替，必须给出与密码相关的明确提示（如"密码错误，请重新输入"）。

**REQ-001-G**
WHEN 用户在兜底密码输入窗口输入密码并确认 THE SYSTEM SHALL 用该密码再次尝试打开压缩包，成功后将该密码加入已存归档密码集合。

### 4.3 约束

**REQ-001-H**
WHILE 归档密码管理界面处于前台 THE SYSTEM SHALL 保持密码列表与持久存储一致，新增/删除即时落盘。

**REQ-001-I**
IF 归档密码集合为空 THEN 加密压缩包打开时 THE SYSTEM SHALL 直接弹出密码输入窗口，不进行无意义的空尝试。

## 5. 验收条件

1. 归档密码有独立全屏界面，一条密码一个记录，可新增可删除，返回手势正常回退。
2. 加密压缩包打开时自动尝试已存密码，全部失败后必弹密码输入窗口。
3. 密码相关失败不再被"没有内容""文件缺失"等无关提示掩盖。
4. 手动输入的密码成功后自动加入密码库。
5. 现有本地/SMB/WebDAV 三路共用的密码记忆库行为不破坏。

## 6. 职责边界

- 不负责压缩包解压算法本身
- 不负责 SMB/WebDAV 连接密码（那是另一套凭据）
- 不负责密码的加密存储方案（沿用既有 stringSetPref 持久化）
