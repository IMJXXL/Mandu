# 需求规格：合并/增强按钮重组

- **需求ID**: REQ-005
- **标题**: 首页合并/增强按钮重组与合并功能
- **优先级**: P1（高）
- **基线 commit**: eb2ac412
- **状态**: 待评审

## 1. 背景与问题

首页多选模式下：上方有"全选"与"超分"按钮（超分把选中加入队列），底部有"增强"按钮。用户期望重组：
- 上方"超分"保留；
- "增强"挪到上方，点击后弹出选项菜单（同原底部增强的选项）；
- 底部"增强"位置改为"合并"；
- 合并：选中的多本（如 a1–a5,5）合并成一本 A，弹窗改名，书架只显示 A，点 A 才看到 a1–a5；
- 封面按正常逻辑从 a1–a5 里选一个；
- 只选一本时合并按钮置灰，需两本以上才能合并；
- 只选中已合并的 A 时，按钮变"解散"，把 A 释放回 a1–a5；
- 同时选了 A 和普通书 B 时，仍为"合并"。

## 2. 核心输入

1. 用户在首页多选模式下的选择集合（普通书 / 已合并书）
2. 用户对上方"超分"/"增强"与底部"合并/解散"的点击
3. 合并弹窗中用户输入的新书名

## 3. 核心输出

1. 合并后的虚拟书 A（书架展示单本，点开可见成员）
2. 解散后恢复的成员书列表
3. 超分队列的新增项
4. 增强选项菜单

## 4. EARS 需求

### 4.1 按钮位置重组

**REQ-005-A**
WHEN 首页进入多选模式 THE SYSTEM SHALL 在上方工具栏保留"超分"按钮（把选中书加入超分队列），并将"增强"按钮也置于上方工具栏。

**REQ-005-B**
WHEN 用户点击上方"增强"按钮 THE SYSTEM SHALL 弹出增强选项菜单（与原底部增强选项一致），供用户选择增强方式。

**REQ-005-C**
WHEN 首页进入多选模式 THE SYSTEM SHALL 在底部操作栏原"增强"位置显示"合并"按钮（或选中已合并书时显示"解散"）。

### 4.2 合并功能

**REQ-005-D**
WHEN 用户选中两本及以上普通书并点击"合并" THE SYSTEM SHALL 弹出改名弹窗，用户输入新名后将其合并为一本虚拟书 A，书架上以单本 A 展示，点击 A 才能看到成员 a1–a5。

**REQ-005-E**
WHEN 合并生成虚拟书 A THE SYSTEM SHALL 按正常封面逻辑从成员 a1–a5 中选取一个作为 A 的封面。

**REQ-005-F**
WHEN 用户仅选中一本普通书 THE SYSTEM SHALL 将"合并"按钮置灰（不可点击），至少选中两本普通书方可合并。

**REQ-005-G**
WHEN 用户仅选中一本已合并书 A 并点击"解散" THE SYSTEM SHALL 将 A 解散，成员 a1–a5 重新作为独立书回到书架，A 不再存在。

**REQ-005-H**
WHEN 用户同时选中已合并书 A 与普通书 B（或两个已合并书） THE SYSTEM SHALL 显示"合并"按钮，点击后执行合并（将 A 的成员与 B 一并合并为新虚拟书）。

### 4.3 约束

**REQ-005-I**
WHILE 合并/解散操作执行 THE SYSTEM SHALL 保持成员书的阅读进度、书签、标签等既有属性不丢失。

**REQ-005-J**
WHEN 合并弹窗展示 THE SYSTEM SHALL 提供默认书名（可取首位成员名或"合并合集"），用户可修改后确认或取消。

**REQ-005-K**
IF 用户在合并弹窗取消 THE SYSTEM SHALL 不执行合并，选择集合与书架状态不变。

## 5. 验收条件

1. 多选模式上方有"超分"与"增强"，增强点击出选项菜单。
2. 底部原增强位置为"合并"（或选中已合并书时为"解散"）。
3. 选中≥2 本普通书可合并，弹窗改名，书架显示单本 A，点 A 见成员。
4. 封面取自成员正常逻辑。
5. 仅选 1 本时合并置灰。
6. 仅选已合并 A 时按钮为"解散"，点击后 A 消失、成员回书架。
7. 选 A + B 时仍为"合并"。
8. 合并/解散不丢成员的进度/书签/标签。

## 6. 职责边界

- 不负责超分算法本身（仅保留入队入口）
- 不负责增强算法本身（仅保留选项菜单入口）
- 不负责封面提取的具体实现（沿用既有封面逻辑）
- 合并为书架层的逻辑聚合，不改变成员书的物理文件
