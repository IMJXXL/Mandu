# 诊断日志对照表（内部维护文档，不随 APK 发布）

> 目的：诊断日志已全面中性化（防止外部人员从日志推断技术路线）。
> 本文是短码 → 实际含义的对照表，排障与后续维护必读。
> 原则：**用户拿日志能看出自己的问题；外部人员推不出我们的实现。**
> 新增打点时必须同步更新本表。

## 一、导出物结构（DiagExporter）

| 段 | 内容 | 限量 |
|---|---|---|
| 头部 | 设备品牌/型号/Android 版本/ABI/应用版本/安装更新时间 | — |
| crash_logs | 最近 5 份崩溃日志（每份末尾 64KB） | 5×64KB |
| anr_log | ANR 看门狗记录末尾 8KB | 8KB |
| diag_stages | 阶段打点时间线末尾 256KB | 256KB |

- diag_stages.txt 超 2MB 时下次启动自动截尾保留末尾 256KB。
- 导出时统一脱敏：`com.mangareader.*` 类名 → `m.*`；`com.hippo.ehviewer.*` → `h.*`；`/storage/...`（含漫画文件名的路径）→ `<book>`；`/data/user/...` → `<app>`。
- 不导出：logcat、系统 trace、SharedPreferences、线程名。

## 二、打点对照表（diag_stages 时间线）

### 生命周期

| 日志原文 | 实际含义 | 排障价值 |
|---|---|---|
| `==== session vX.Y ====` | 本次冷启动会话开始（版本号） | 区分会话 |
| `app.onCreate: enter` | 进程启动入口到达 | 极早期崩溃的最后一个标记 |
| `app.onCreate: phase-1 done` | 内置底层库加载完成 | 库加载失败时停在此前 |
| `app.onCreate: phase-2 done` | 启动检查步骤 2 完成 | — |
| `app.onCreate: phase-3 done` | 启动检查步骤 3 完成 | — |
| `app.onCreate: background maintenance started` | 后台维护任务已启动 | — |
| `mainActivity: first composition committed` | 首屏渲染完成（多次=Activity 重建） | 启动卡顿定位 |
| `library: books loaded n=77` | 书架载入完成（77 本） | 书库规模 |

### 阅读

| 日志原文 | 实际含义 | 排障价值 |
|---|---|---|
| `readerView mode=FLIP vert=false pages=47 start=34` | 打开阅读器（页面模式/是否条漫/页数/起始页） | 打开失败时看到达与否 |
| `pageCount=N` | 章节页数确认 | — |
| `page cur=35` | 翻页心跳（当前页号，≥5 秒一条） | 翻页是否正常进行 |
| `pageDecode idx=35 1234ms` | 单页解码整链路耗时（**>300ms 才记录**） | 慢页取证（epub/zip 慢） |
| `merge 12ms` | 双页拼接耗时（**>50ms 才记录**） | 切双页"要加载一下"取证 |
| `seg expand in=N out=M unprobed=K` | 超长页分段展开（入/出/未探测数） | 长图/PDF 分段问题 |
| `seg ok / seg fallback idx=.. seg=..` | 分段渲染成功 / 降级 | 分段渲染失败定位 |
| `trimEx idx=.. <异常>` | 裁白边异常 | — |
| `w: 1/2/3/4 <长度>` | 条漫滚动状态机事件（1=延迟处理 2=用户接管 3=重新锚定 4=放弃锁） | 条漫滚动异常 |

### 远程（WebDAV/SMB 等网盘源）

| 日志原文 | 实际含义 | 排障价值 |
|---|---|---|
| `remote: open zip begin` | 开始打开网盘书（扩展名） | — |
| `remote: open ok 1234ms` | 打开成功+总耗时 | **"时快时慢"核心证据** |
| `remote: open timeout 15000ms` | 打开超时（15 秒上限） | 服务器无响应 |
| `remote: open fail 890ms` | 打开失败 | 配合异常信息 |

### 画质增强

| 日志原文 | 实际含义 | 排障价值 |
|---|---|---|
| `enhance: on engine=gpu acc=true 820ms` | 增强就绪（engine=实际引擎 cpu/gpu/npu；acc=是否图形加速；耗时 ms） | 无此行=增强从未启动；engine 与面板所选不符=引擎自动回落（见下行 skip/熔断） |
| `enhance: off (init)` | 初始化失败，直通原图 | "增强无效"常见原因 |
| `enhance: npu skip cdsp=false arch=69 reg=false` | 选了 NPU 但没走成：cdsp=/dev 节点预检（ROM 命名差异可假阴性，仅提示不作门）；arch=芯片代号（0=QNN 探测不到/不受支持）；reg=当前档位+降噪强度有无已装模型包 | reg=false→装对应代号的模型包插件；arch=0→设备或运行时探测失败；cdsp=false 而 arch>0→预检假阴性（已被放行不会出现此行） |
| `enhance: npu fail n=1/2` | NPU 推理失败计数（1~2 次） | 模型包与固件兼容问题前兆 |
| `enhance: npu off n=3` | NPU 连续 3 次失败→本会话熔断回退 | NPU 突然失效的原因（重进应用或重新切档解除） |
| `enhance: acc fail n=1/2` | 加速推理失败计数（1~2 次） | 新驱动兼容问题前兆 |
| `enhance: acc off n=3` | 连续 3 次失败→本会话回退 | 增强突然失效的原因 |
| `enhance: safe mode (previous session abnormal)` | 上次会话异常，本次强制安全模式 | 历史崩溃残留降级 |

## 三、排障速查

| 用户反馈 | 看什么 |
|---|---|
| 打开书慢/时快时慢 | `remote: open ok` 的 ms 波动 + `pageDecode` 慢页 |
| 开双页要加载一下 | `pageDecode`（两页各一条）+ `merge` |
| 画质增强无法启用 | 有无 `enhance: on`；`off (init)` / `acc off` / `safe mode` 哪条 |
| 选了 NPU 还是慢（实际在走加速/处理器） | `enhance: on engine=?` 与 `npu skip` 三状态（reg=false 装模型包；arch=0 探测失败） |
| NPU 用一阵就失效 | `enhance: npu off n=3`（熔断回退，重进解除） |
| 封面不出（防封控模式） | 服务器标记文案 + 该模式设计如此（阅读后自动补） |
| 启动崩溃 | session 行后最后一条到达的阶段 |

## 四、改动纪律

1. 新增打点：中性措辞（禁止出现内部类名/机制名/协议名/第三方库名），并同步更新本表。
2. 禁止在打点中包含用户文件路径、书名。
3. 高频路径必须带阈值或节流（参考 pageDecode >300ms、merge >50ms、page cur 5s）。
